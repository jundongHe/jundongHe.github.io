本页目的：把该 skill 的用途、硬边界、标准工作流、保真规则与推荐提示词保存在本站。即使上游仓库停止维护，这里仍可查阅核心用法。完整可运行插件仍需原仓库的 MCP 与安装脚本。

1. 这是什么

面向科研插图的 Codex 插件。它会启动桌面版 draw.io，通过仅限本机的 MCP 通道直接调用 draw.io 自身的图模型 API。你可以看见形状、文字、箭头、配色和布局按步骤出现在画布上。

不模拟系统鼠标/键盘，也不先生成 XML 再打开。只有可见画布上的图绘制完成后，才把当前图模型保存为 .drawio。

2. 用途（为什么值得留）

  • 参考图可编辑复刻：PNG / JPEG / SVG / PDF 页 → 尽量变成可改的文字、形状、连线、图例
  • 论文与组会用图：机制图、实验流程、系统架构、通路图等，输出可继续在 draw.io 里改
  • 边画边审：按区域绘制 → 截图审查 → 修正 → 再继续
  • 导出交付：保存 .drawio，导出 PNG / SVG / PDF / JPG

3. Skill 触发描述（原文要点）

用于：在可见的 draw.io 桌面画布中，通过 draw.io 自身的 graph API，重绘、描摹、修改、检查或导出静态科研图与示意图。

适用场景包括：希望逐步观看绘制过程；明确拒绝「先生成 XML 再打开」或系统键鼠自动化；提供参考图要重建为可编辑几何；需要最终 .drawio / PNG / SVG / PDF / JPG。

4. 硬边界（必须遵守）

  • 只通过 live MCP 控制 draw.io 内部 graph / model API
  • 禁止使用操作系统级鼠标、键盘、窗口或全屏自动化
  • 禁止以「先写好 XML 再打开」作为主要绘制方式；只有可见图元已存在后才序列化 .drawio
  • 截图仅用于检查 draw.io 画布本身，不是通用屏幕控制

5. 标准工作流（10 步）

  1. 先用视觉能力看清参考图（PDF 先渲染相关页）。不要只是把位图嵌进去就算重绘。
  2. 拆成可编辑图元：画布比例、分面、容器、节点、文字、箭头、图例、重复母题、颜色、线宽、字体、层级。无法用图元忠实表达的部分标出，可考虑位图区域。
  3. 调用 drawio_live_launch（建议步进延迟 400–1000 ms），用 drawio_live_status 确认 graph_ready=true 再画。
  4. 向实时画布添加几何：单步用 drawio_live_add_shape / drawio_live_add_edge；批量用带非零 step_delay_ms 的 drawio_live_draw_sequence。从一开始就用稳定、有语义的 cell id。
  5. 每个逻辑区块完成后调用 drawio_live_screenshot，对照参考图检查。
  6. 在实时图上迭代：drawio_live_inspect + drawio_live_update_cell 改标签、样式、位置、大小；用 drawio_live
